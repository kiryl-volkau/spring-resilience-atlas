How to read this report

Code hints: from the code, before any audit

High
A pattern that loses or corrupts work when it fires: work handed to an in-memory thread after the caller was answered, a message sent inside an uncommitted transaction.
Medium
A pattern that duplicates or stalls work under retries, restarts or several replicas: no idempotency check, a job without a lock, a remote call inside a transaction, state in memory.
Low
Worth a look, rarely a defect on its own: a cache in memory, a background thread, an in-process event inside a transaction.
No pattern
Nothing matched on the path the scanner read. This is not a clean bill of health.
Not analysed
The code behind the operation was never read: Kotlin, Groovy and files the Java parser could not handle are scanned for entry points only. Nothing is known about their risk.

The scanner reads the entry method, the methods of its class that it calls, and the methods of injected beans a few levels deep. A hint says where to look first; it is not a verdict. A mitigation that lives outside the code (a unique constraint, a dead-letter queue, a single replica) is invisible here.

Status: from an audit, with evidence

Broken
A verified finding of critical or high severity: acknowledged work can be lost, duplicated or corrupted.
Smells
Fragile but working today, or suspected by the quick check and waiting for a deep audit.
OK
A flow was traced with file-and-line evidence and the audit rules found nothing.
Checked (quick)
A small model checked every high and medium pattern of the operation against the code and found each one mitigated or refuted. Low hints and anything the scanner did not see were not checked.
Not audited
No verdict, or the verdict is stale because its files changed. Never shown as OK.

Statuses are computed by the report generator from verdict and finding records. No model writes a colour into this page, and a code hint never turns into a status.

What the code does

Discovery status

static
Found from annotations and declarations whose values the scanner resolved exactly.
inferred
Found through a rule that can be wrong: an inherited mapping, a naming convention, regex-only parsing (Kotlin, Groovy, files javac could not parse).
unknown
Something is there but its target is not known from the sources, such as a generated interface that has not been built.
